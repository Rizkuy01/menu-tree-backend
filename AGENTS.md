## 1. What this project is

A **technical test submission**: "Fullstack Menu Tree System".
A hierarchical menu tree (unlimited depth) with CRUD, built as a Go backend + React/Next.js frontend.

Evaluation weights: Code Quality 30%, Functionality 30%, UX 20%, Documentation 10%, Bonus 10%.
Submission: public GitHub repo, README, screenshots or video demo.

### Requirements recap

**Backend (Go preferred):** REST CRUD, parent-child hierarchy, input validation + error handling,
PostgreSQL/MySQL, Swagger/OpenAPI docs. Bonus: move + reorder endpoints.

**Frontend:** React/Next.js + TypeScript + Tailwind. Display tree, add at any level,
edit (inline or modal), delete with confirmation, expand/collapse, search/filter,
responsive, loading + error states. Bonus: drag-and-drop, state management (Zustand/Redux/Context).

**Bonus:** Docker (compose dev + multi-stage prod), unit tests, performance, smooth DnD.

**Deliverables:** clean folder structure, README (setup, dev, prod, Docker, Swagger link,
tech choices + architecture decisions), migrations, `.env.example`, tests.

## 3. Folder structure

```
menu-tree-backend/
├── cmd/api/main.go            # entry point + swagger general annotations
├── internal/
│   ├── config/                # env loading
│   ├── database/              # pgx pool connection
│   ├── model/                 # Menu, MenuNode, sentinel errors
│   ├── repository/menu.go     # SQL only
│   ├── service/menu.go        # business rules (validation, depth, tree building)
│   ├── handler/               # HTTP handlers + response helpers
│   ├── dto/menu.go            # request bodies + validation tags
│   └── router/router.go
├── migrations/                # 000001_create_menus.{up,down}.sql
├── docs/                      # GENERATED by swag — do not edit by hand
├── .env  (git-ignored)        # real secrets
├── .env.example               # fake values only
└── AGENTS.md
```

Layering rule: **handler → service → repository**.
- Handler: parse input, call service, map result/error to HTTP. No SQL, no business logic.
- Service: business rules. Depends on the `MenuRepository` **interface** (mockable in tests).
- Repository: SQL only, parameterized queries (`$1, $2`). Never concatenate user input.

## 4. Data model

```sql
CREATE TABLE menus (
    id         UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name       VARCHAR(255) NOT NULL,
    parent_id  UUID REFERENCES menus(id) ON DELETE CASCADE,
    depth      INT NOT NULL DEFAULT 0,
    position   INT NOT NULL DEFAULT 0,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_menus_parent_id ON menus(parent_id);
CREATE INDEX idx_menus_parent_position ON menus(parent_id, position);
```

Design: adjacency list. `parent_id IS NULL` = root menu. `position` is 0-based among siblings.
`depth` is stored (shown in the UI) and must be kept consistent on create/move.
Deleting a parent cascades to all descendants.

## 5. API contract (base path `/api`)

| Method | Path | Body | Notes |
|---|---|---|---|
| GET | `/menus` | — | Full tree: roots with nested `children` |
| GET | `/menus/:id` | — | Single menu, includes `parent_name` |
| POST | `/menus` | `{name, parent_id?}` | depth computed from parent; appended last among siblings |
| PUT | `/menus/:id` | `{name}` | Only name is editable |
| DELETE | `/menus/:id` | — | 204; cascades |
| PATCH | `/menus/:id/move` | `{parent_id?, position?}` | `parent_id: null` = root; `position` omitted = last |
| PATCH | `/menus/:id/reorder` | `{position}` | Same parent; clamped to last index |
| GET | `/health` | — | `{"status":"ok"}` (outside `/api`) |

Error format (always):
```json
{ "error": { "code": "VALIDATION_ERROR", "message": "..." } }
```

| Code | HTTP | When |
|---|---|---|
| `VALIDATION_ERROR` | 400 | bad body, empty name, negative position |
| `INVALID_ID` | 400 | path id is not a UUID |
| `NOT_FOUND` | 404 | menu not found |
| `PARENT_NOT_FOUND` | 404 | target parent not found |
| `INVALID_MOVE` | 409 | move into itself or a descendant (cycle) |
| `INTERNAL_ERROR` | 500 | unexpected; details only in server log |

## 7. Commands

Developer shell is **Git Bash on Windows (MINGW64)**; use Bash syntax.

```bash
# run
go run ./cmd/api

# load DATABASE_URL from .env into the shell, then run migrations
export $(grep DATABASE_URL .env | xargs)
migrate -path migrations -database "$DATABASE_URL" up

# regenerate swagger after ANY annotation/struct/endpoint change
swag init -g cmd/api/main.go -o docs

# deps / format / checks
go mod tidy
gofmt -l .
go vet ./...
go test ./...
```

## 9. Rules for the agent

1. **Never commit secrets.** `.env` must stay git-ignored; `.env.example` holds fake values only.
2. Keep the handler → service → repository layering. Do not put SQL in handlers or HTTP types in services.
3. All SQL parameterized. Multi-step writes that must be atomic use a transaction.
4. Schema changes need a **new migration file** (`migrate create -ext sql -dir migrations -seq <name>`); never edit an applied migration.
5. After changing swagger annotations, DTOs, models, or routes, run `swag init -g cmd/api/main.go -o docs`. Never hand-edit `docs/`.
6. Return errors via `respondError` / `handleServiceError`; map new sentinel errors there. Never leak internal error text to clients.
7. Make small, reviewable changes; run `gofmt`, `go vet`, `go build ./...` before declaring done.
8. The developer is **new to Go**: prefer simple, idiomatic code, add short comments on non-obvious Go concepts
   (pointers for nullable fields, `defer`, transactions, `context`), and summarize what changed and why.
9. Do not claim something works unless it was actually run. If you cannot run it (e.g. Docker, DB access), say so.
10. Commit with conventional messages (`feat:`, `fix:`, `test:`, `docs:`).

## 10. Known pitfalls (already hit once)

- `uuid.UUID` is a `[16]byte`; swag renders it as a number array unless the field has
  `swaggertype:"string" format:"uuid"`.
- Swagger response types must be **exported** (`ErrorResponse`, not `errorResponse`).
- `swag` CLI and the `github.com/swaggo/swag` library versions must match
  (`go get github.com/swaggo/swag@latest` + `go install github.com/swaggo/swag/cmd/swag@latest`),
  otherwise `docs.go` fails with `unknown field LeftDelim`.
- Use Neon's **direct** (non-pooled) connection string with `sslmode=require`.
- Nullable columns map to pointers (`*uuid.UUID`, `*string`); nullable params need a cast in SQL (`$1::uuid`).
- When testing with curl in Git Bash, a stray newline inside a quoted UUID breaks the request; use shell variables.
